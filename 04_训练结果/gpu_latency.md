# 推理延迟与批量吞吐（YOLO26s 部署权重，GPU 为主，CPU 对照）

测量日期：2026-11-28。模型为 `02_模型权重/best.pt`（YOLO26s，NEU-DET 训练），imgsz=320，conf=0.25，NMS IoU=0.45。
脚本：`01_程序源码/steel-defect-yolo/scripts/cpu_latency.py`（名字是历史原因，`--device 0` 即测 GPU）。

## 设置

- 数据：NEU-DET `test`，每轮预热 10 张，计时 100 张，`--seed 0`，各轮用同一组图片、同一顺序
- 环境：PyTorch 2.14.1+cu126，CUDA 12.6，Ultralytics 8.4.202；CPU 为 AMD Ryzen 9 8945H（16 逻辑核心，torch 线程 8）
- GPU 重复 4 轮，每轮新起一个 Python 进程，共 400 张；CPU 重复 1 轮，100 张
- 计时为端到端 `model.predict`，含预处理、推理、NMS 和后处理；不含磁盘读取

## 1. GPU 单张端到端延迟（RTX 4060 Laptop，4 轮合并 400 张）

| 指标 | 数值 (ms) |
|---|---:|
| 均值 | 8.99 |
| 标准差 | 0.55 |
| 最小值 | 7.87 |
| P50 | 8.95 |
| P90 | 9.67 |
| P95 | 9.95 |
| 最大值 | 11.34 |

各轮均值：8.91 / 8.77 / 9.19 / 9.08 ms（标准差 0.51 / 0.46 / 0.63 / 0.52）。
Ultralytics 自报纯推理耗时：均值 7.48 ms，标准差 0.45 ms；预处理 0.35 ms，后处理 0.94 ms。
权重加载 41 至 60 ms，首张冷启动约 1.9 至 2.0 s（含 CUDA 上下文和 cuDNN 初始化）。

## 3. 同一权重在 CPU 上的延迟（对照，1 轮 100 张）

| 指标 | GPU | CPU |
|---|---:|---:|
| 均值 (ms) | 8.99 | 24.98 |
| 标准差 | 0.55 | 2.45 |
| P95 | 9.95 | 27.05 |
| 最大值 | 11.34 | 44.45 |
| 纯推理 | 7.48 | 23.73 |
| 批量 8 张一组 (ms/张) | 2.0 | 14.8 |

同一权重、同一脚本、同一组图片，GPU 比 CPU 快约 2.8 倍（24.98 / 8.99），延迟波动也更小。

## 说明

- 计时为端到端墙钟时间。GPU 上 Ultralytics 在推理后调用 `torch.cuda.synchronize()`，每张图的耗时已包含等待 GPU 算完的时间。
- 笔记本的 CPU 和 GPU 都受功耗与温度影响，重复运行会有几个百分点的波动；4 轮均值在 8.77 至 9.19 ms 之间。
- 系统的批量接口目前逐张处理，没有利用批量推理，20 张约 0.18 s（8.99 ms × 20，不含上传和写盘）。
